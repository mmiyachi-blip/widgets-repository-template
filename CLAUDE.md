# Working in this repo

Read **[AGENTS.md](AGENTS.md)** in this same directory first — it's the
authoritative local contract: per-widget `widget.json` / `connectors.json`,
the `./bin/build-registry.sh` build script, validation rules, and the commit
workflow. This file only adds a few notes AGENTS.md doesn't cover.

- **Load the `gainsight-cc-developer-studio` skill** before writing or
  editing a `widget.json`, `connectors.json`, or widget entry file — it has
  the current Developer Studio platform reference (widget config field
  types, Shadow DOM / Widget SDK, connector authentication types, Jinja2
  template variables and filters, design tokens) cached locally, so there's
  no need to fetch the online docs from scratch each time.
- **`main` is watched by Developer Studio Sources and auto-publishes on
  push** — there is no staging branch. Before pushing: validate JSON
  (`jq . widgets/<name>/widget.json` / `connectors.json`), run
  `./bin/build-registry.sh --dry-run` to confirm it processes cleanly, and
  prefer testing a new connector via **Test Connection** in the Developer
  Studio admin UI before wiring it into a widget.
- A widget's directory name becomes its registry `type`, which is its
  stable identity in Developer Studio (existing page placements and saved
  config are keyed on it). Renaming an existing widget's directory changes
  that identity — don't do it without a good reason, and if you do, expect
  to re-place the widget on its page(s).
- Do not hand-edit `extensions_registry.json` or `connectors_registry.json`
  — they're generated by `./bin/build-registry.sh` from the per-widget
  source files and will be silently overwritten (or, for a widget/connector
  that only exists in the generated file with no matching source, silently
  dropped) the next time the build script runs for real.
